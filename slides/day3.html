The hidden cost

A batch does not exist until its requests arrive

average wait = (b - 1) / (2 x rate)

plus the batch's own time. At 2 leaves per second a batch of 8 makes the average leaf wait about 1.75 s before computing starts.

  • Office, 2 leaves per second: batch 1 is the only batch that meets the budget.
  • Night archive, 200 per second: larger batches fill fast and serve more.
  • Servers batch dynamically: up to b requests or t milliseconds, whichever comes first.

Quantisation

Store numbers as small integers with a scale, and map them back when needed

real value = scale x (integer - zero point)

8 bits give 256 levels; 4 bits give 16. The scale is chosen per tensor, per channel or per block of weights.

  • Smaller files: a quarter (8-bit) or an eighth (4-bit) of float32.
  • Faster only where kernels compute on integers or blocks.
  • Lossy: quality is measured again, by group.

Finer scales (per channel, per block of 32) cost a few bytes and keep more quality: an outlier weight then spoils only its own block.

For a classifier

Static quantisation calibrates activation ranges on real data; dynamic computes them on the fly

Sources: ONNX Runtime documentation, quantising ONNX models (static and dynamic). Post-training quantisation is what the entry asks for; quantisation-aware training is the fallback when post-training loses too much, at the price of training again.

Read the table twice

A smaller file is not a faster model: the runtime decides

Expand once

Small download and disk; same memory and speed as float32.

Expand per call

Small memory; slower in a general framework that expands before multiplying.

Compute on blocks

Small memory and faster decoding, because fewer bytes are read per token. Needs a runtime built for it.

This is the lesson participants most often get wrong in capstones: they quantise, see no speed-up, and conclude quantisation does not work. Ask them which column their runtime is in.

Pruning

Zeroing weights saves nothing on dense kernels; removing channels does

Unstructured

Set the smallest weights to zero anywhere. The matrices keep their shape: a dense kernel multiplies zeros as fast as other numbers.

Structured

Remove whole filters (channels). Every matrix gets smaller, so every layer does less work.

Unstructured sparsity pays off only with sparse kernels or special hardware patterns, and compresses well on disk. Source: Han, Mao and Dally, Deep compression (arXiv 1510.00149), for pruning combined with quantisation.

Lab 3.4

Score each filter by its L1 norm, keep the top half, copy the weights

scores = U.channel_scores(base)           # one tensor per convolution
keep = [torch.sort(torch.topk(s, len(s) // 2).indices).values
        for s in scores]
pruned = U.prune_channels(base, keep)     # a smaller Waraqa, weights copied
U.train_steps(pruned, x_tr, y_tr, steps, lr=5e-4)   # a short fine-tune

Removing an output channel of one convolution also removes the matching input channel of the next: prune_channels handles that. L1 norm is a cheap score; others use the batch norm's scale or the effect on the loss.

A third route, as a concept

Distillation trains the small model to imitate the large one's probabilities

  • The teacher's output says not only "rust" but "rust, a little like leaf spot".
  • The student learns from those soft targets as well as the labels.
  • Often beats the same small model trained on labels alone.

When to choose which

Prune when you own a trained large model and want a cheap result; shrink or distil when you train anyway and want the simplest artefact.

Concept level only, as the entry says. Source: Hinton, Vinyals and Dean, Distilling the knowledge in a neural network (arXiv 1503.02531). AE-310 teaches distillation in practice.
