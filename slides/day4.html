Review of Day 3

Why was the 4-bit file not faster?

Hasad's 4-bit file is about a sixth of the 32-bit file's size. Loaded with "expand once", it decodes no faster than the 32-bit model once the machine is quiet. Why?

The 4-bit file holds the same bytes as the 32-bit one
At load the weights became float32 again, so each decode step reads as many bytes as before
The key-value cache got larger in 4 bits
The tokenizer is slower for quantised models
Why. Decoding at batch 1 is memory-bound; speed comes from reading fewer bytes per token, which needs kernels that compute on the 4-bit blocks.

Answer: B. Ask who loaded Hasad with "expand once" in Lab 3.3 and compare the file size with the decode speed in their table. A 4-bit file pays off only where the runtime computes on the blocks, as llama.cpp does with its quantised types.

Session 1

Export to a portable runtime

  • Export a model to an exchange format with a dynamic batch axis

01
Exchange formats

An exported file carries the graph and the weights, without the training stack

Smaller install

A runtime instead of a training framework on every farm laptop.

Optimised once

Fusions and constant folding happen when the session opens, not at every start-up compile.

One file, many devices

The same file on Windows, Linux and phones, with the runtime for each.

ONNX is the exchange format the labs use. The slot "portable inference runtime" has interchangeable examples: ONNX Runtime, ExecuTorch (PyTorch's on-device runtime), LiteRT (Google AI Edge). Name the capability first.

Checkpoint

Where do you look first?

The exported Waraqa gives different classes from PyTorch on field photos. Feeding both the identical input tensor, their logits agree within 1e-6. Where is the fault?

In the exported file: re-export with another opset
In the preprocessing: the two pipelines build different tensors from the same photo
In floating-point rounding inside the runtime
In the model's training, which must be redone
Why. Identical inputs, identical outputs: the model half is proven, so the difference is in how each side turns a photo into a tensor.

Answer: B. The parity test on one shared tensor isolates the model; the first planted fault in Lab 4.1 is on the input side (the second is the fixed batch axis). Ask which preprocessing step each pipeline runs.

Session 2

A benchmark you can trust

  • Write a benchmark that controls warm-up, repetitions and input mix
  • Report percentiles with bootstrap confidence intervals
  • Re-run a benchmark and judge the agreement
02
Benchmark design

Control what you can, record what you cannot

Controlled

Warm-up calls, number of repetitions, a fixed input mix in a file, batch size, threads, the model file.

Recorded

Processor, memory, operating system, runtime version, power mode, the load at start.

The test of a benchmark. Another person runs it on the same kind of machine and gets a median within 10%.

That is LO6's evidence, word for word: a benchmark script and report that another participant re-runs within 10% of the reported median.

A fixed input mix

Time 40 leaves in the field's crop shares, saved to a file

Tomato

  • One leaf measures one leaf; real traffic is mixed.
  • The file (mix.npy) makes a re-run see the same inputs.
  • For a language model the mix is prompts of the field's lengths.

A classifier's time hardly depends on the leaf; a language model's depends a lot on the prompt and answer lengths, so there the mix matters most.

Percentiles with intervals

A bootstrap interval says how far the median could move on a re-run

rng = np.random.default_rng(206)
boots = np.percentile(
    ms[rng.integers(0, n, (2000, n))], q, axis=1)
low, high = np.percentile(boots, [2.5, 97.5])
  • Resample the timings with replacement, recompute the percentile, 2,000 times.
  • The middle 95% of those values is the interval.
  • The 95th percentile's interval is wider: it rests on fewer calls.

Bootstrapping assumes the calls are independent; consecutive timings on a laptop are slightly correlated (turbo, background tasks). Repeating the whole benchmark, as step 5 does, is the honest complement.

When a re-run disagrees

Find the difference in conditions before reporting either number

The machine

Load at start, power mode, battery, temperature, another processor.

The settings

Threads, batch, runtime version, graph optimisation level.

The inputs

The same mix file? The same model file, byte for byte?

The follow-up task after the course is exactly this: the benchmark re-run on a second device, with a short comparison note. bench.py records the load at start for this reason.

Checkpoint

What do you report?

The 8-bit median is 3% lower than the 32-bit median, and the two 95% intervals overlap by most of their width. What is the honest report?

On this machine at batch 1 the two are not distinguishable; the 8-bit file is smaller
The 8-bit model is 3% faster
The two models are exactly as fast
Repeat until the intervals separate, then report the difference
Why. Overlapping intervals mean the data cannot separate the two; report that, and the differences you can show (size).

Answer: A. The size difference is measured and certain; the speed difference is not. Point to the re-run rule of Lab 4.2: a second run within 10% before any claim.

Session 3

Quality must survive

  • Compare two models on the same items with a paired test
  • Put an interval on an accuracy difference
  • Accept or reject a variant on the quality floor by crop type
03
Nama's quality floor

At most 1 point lost overall and 2 points on any crop

  • Compression changes errors unevenly: faint lesions, narrow leaflets, the rarest crop.
  • So every variant is checked overall and per crop, and Hasad per language variety (Lab 3.3).
  • Fairness, the first of SDAIA's AI Ethics Principles, shows up here as a per-group check.

The farmers behind a group

Date palm is one leaf in ten in the data and the main crop of many farms in some regions.

Sources: SDAIA AI Ethics Principles (Fairness is the first principle). The floor numbers are the case's: Ghadeer set them. Ask the room what group they would check in their own capstone.

A paired comparison

Compare two models on the same leaves; only the disagreements carry information

Variant rightVariant wrong
Original rightboth rightb: lost
Original wrongc: gainedboth wrong

Difference in accuracy = (c - b) / n. McNemar's exact test asks whether b and c could come from a fair coin.

Pairing removes the difficulty of each leaf from the comparison; two separate accuracies would carry that noise. Lab 4.3 uses scipy's binomtest for the exact test and a paired bootstrap for the interval.

Reading an "uncertain"

An uncertain verdict is a request for evidence, not a pass

  • About 200 date-palm leaves: one leaf is half a point.
  • The interval says how many more leaves would settle it.
  • Ask Nama for more labelled date-palm leaves before shipping, or keep the larger model for that crop.

Checkpoint

Accept, reject or uncertain?

A variant loses 0.4 points overall, interval [-1.3, +0.5], and 1.0 point on date palm, interval [-4.0, +2.0]. The floor is 1 point overall and 2 per crop. What is the verdict?

Accept: both losses are within the floor
Reject: the intervals go below the floor
Uncertain: the estimates pass but both intervals reach below the floor
Accept overall; per-crop intervals do not matter
Why. The data are consistent with a loss beyond the floor; more evidence is needed before the variant ships.

Answer: C. Date palm is the smallest crop, so its interval is the widest; more held-out date-palm leaves narrow it. This is the reading Lab 4.3 asks for on every row.

Energy per prediction, as an estimate

Time per prediction times an assumed power, with the assumption written next to it

Wh per 1,000 = watts x seconds per prediction x 1,000 / 3,600

The course assumes 15 W for a thin laptop's processor under load; use your laptop's specification if you know it.

  • No power meter in the room: this is an estimate, and says so.
  • Proportions between variants are meaningful; absolute numbers are rough.
  • Social and environmental benefit, one of SDAIA's AI Ethics Principles, enters the trade-off as a number.

Sources: SDAIA AI Ethics Principles (Social and Environmental Benefits). A better estimate reads the processor's energy counters where the operating system exposes them; not portable across the room's laptops, so the course uses the assumption.

The defence

Eight minutes and four of questions. You re-run your benchmark live, predict the effect of a change the assessor proposes, then measure it.

AI-full in the capstone, which the participant defends live: an assistant may write code, but the participant must predict and explain every number. Profiler outputs, benchmark logs and the commit history are the authenticity evidence. Lab 4.4's last step writes the plan.

Checkpoint

Which variant do you recommend?

Variant A is the fastest but fails the quality floor on date palm. Variant B meets every line, with a p95 of 14.9 ms against a 15 ms budget, measured on the course laptop. What do you recommend?

B, with no further condition

Measure first

Profile, find the binding limit, fix the largest cost, measure again.

Honest numbers

Warm-up, repetitions, fixed inputs, intervals, the machine, a re-run within 10%.
